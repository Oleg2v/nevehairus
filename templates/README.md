# Страницы и шаблоны Elementor (шаг 4)

## Что здесь

| Файл | Что это |
|---|---|
| `pages/home.json` | Главная (`דף הבית`, слаг `דף-הבית`), статическая главная страница сайта: 11 разворотов прототипа `index.html` |
| `pages/main-home.json` | «מעון ראשי – בית לחיים», слаг старого сайта `מעון-ראשי-בית-לחיים` ([redirects.csv](../content/redirects.csv)): 8 разворотов `program-main-home.html` |
| `pages/header.json`, `pages/footer.json` | Шаблоны Theme Builder (Elementor Pro): шапка `nh-masthead`, подвал `nh-colophon`, условие «весь сайт» |
| `media-map.json` | Имя фото → id вложения на тестовом сайте (пишет `test_site.py pages`, только номера) |

Файлы `pages/*.json` **генерируются, руками их не правят**: `python3 -I scripts/build_pages.py` берёт состав страниц из [`plugin/tests/fixtures/pages.php`](../plugin/tests/fixtures/pages.php) и настройки вариантов фикстур виджетов (через `plugin/tests/elementor_data.php` на стенде), затем проверяет рендер: каждый виджет и обе собранные страницы совпадают с фикстурами стенда байт в байт.

Поля файла: `key`, `title`, `slug`, `front_page`, `post_type`, `document_type` (`_elementor_template_type`), `template` (`_wp_page_template`), `conditions`, `page_settings` (`_elementor_page_settings`), `built_from` и `elementor_data` — значение `_elementor_data` в том виде, как его хранит Elementor 4.4.0: один контейнер (Full Width, колонка, gap 0, padding 0), в нём виджеты; у строк повторителей есть `_id`. В `built_from` кроме состава — из чего собрано: `plugin` (версия плагина и sha256 его PHP-файлов) и `inputs_sha256` (те же файлы плюс стенд, фикстуры, манифест фото и сам `build_pages.py`). Поэтому **после любой правки плагина или фикстур JSON надо пересобрать**: `test_site.py pages` откажется работать с файлами, собранными из другого дерева, а его шаг PHP — с сайтом, где PHP плагина не тот, под который собраны файлы (Elementor молча игнорирует незнакомые ключи, а повторитель, сохранённый целиком, хранит строки старого плагина).

Токены подставляются при выкладке: `@media:<имя>` — фото из `prototype/assets/img/manifest.json`; `@page:<key>` — адрес нашей страницы; `@page-id:<key>` — её id (шапка отмечает «מסגרות המגורים» на странице дома); `@home:<путь>` — `home_url()`. Собственные токены ссылок плагина (`#privacy`, `#accessibility`, …) берут страницы из его настроек и для этих двух страниц не годятся.

## Как выложить на тестовый сайт

```bash
python3 -I scripts/build_pages.py              # пересобрать JSON и проверить рендер (без сервера)
python3 -I scripts/test_site.py pages          # план: что будет сделано (только чтение)
python3 -I scripts/test_site.py pages --go     # выполнить
```

`--go`: 0) проверяет, что JSON собраны из этого дерева, и (если есть локальный PHP) прогоняет проверку рендера; 1) загружает 18 фото (самый большой `.webp`, подразмеры делает WordPress) с заголовком `nh:<имя>` и alt из манифеста — уже загруженные находятся по заголовку и не грузятся снова; id вложения попадает в журнал и в `media-map.json` сразу, как WordPress его назвал; 2) одним шагом PHP от имени пользователя скрипта: до первой записи проверяет, что PHP плагина на сайте совпадает с тем, под который собраны файлы, и что в Elementor включена функция Container (без неё контейнеры не выводятся и страницы пусты); затем создаёт (черновиками) или обновляет 4 записи, найденные по мета-полю `_nh_page_key` (чужие записи не трогаются), пишет данные и мета Elementor, публикует их, пересобирает кэш условий Theme Builder и только после этого делает главную статической главной — если шаг упадёт раньше, главная сайта останется прежней; 3) очищает ezCache, проверяет обе страницы (200, нет ошибок PHP, все виджеты, шапка и подвал в обёртке `div`) и печатает адреса. Старые значения и каждое изменение — в журнале `~/.config/nevehairus/test-site-changes.jsonl`: «Чтение» до запуска, а в ответе шага PHP — прежние условия Theme Builder и прежние данные наших записей (включая `_elementor_data`, если он отличался: правки, сделанные в редакторе, не теряются). Повторный запуск безопасен.

CSS Elementor этот шаг сам не чистит (только кэши CSS и ассетов своих четырёх записей): Elementor сам опустошает свой кэш CSS при каждом включении или выключении любого плагина, то есть и когда скрипт включает и выключает Code Snippets, и сам собирает его заново при следующем просмотре.

## Важно

- **Правки этих страниц в редакторе Elementor на сайте перезапишет следующий `pages --go`** (прежний `_elementor_data` останется только в журнале). Менять — в фикстурах или плагине и пересобирать.
- Обёртка шаблонов шапки и подвала в Pro — `div` (настройка документа «HTML Tag»): ориентиры `<header>`/`<footer>` дают наши виджеты, как в прототипе (SPEC D3), без двойных ориентиров.
- Настройки плагина (Settings → נווה האירוס: e-mail, страницы доступности и карты сайта, PDF входов) этот шаг не заполняет: пока их нет, в подвале нет пункта e-mail, а ссылки `#accessibility` и т. п. остаются якорями.
- Ссылки в данных абсолютные, как их сохраняет сам Elementor: `@home:` и `@page:` становятся `https://nevehairus.ussl.co.il/…`, адреса фото тоже. При переносе на другой домен — Elementor → Tools → Replace URL (в JSON слэши экранированы, обычная замена строки их не найдёт).
- `post_content` у страниц пустой: Elementor пишет туда текстовую копию только при сохранении в редакторе, так что поиск WordPress и SEO-плагины не видят текста страниц, пока их не сохранят в редакторе. Для показа страниц это не нужно.
