# Прототип — направление «בית לחיים» (шаг 2)

Живой прототип главной и одной внутренней страницы на HTML, CSS и GSAP плюс страница дизайн-системы. Иврит, RTL, WCAG 2.2 AA (ת"י 5568), `prefers-reduced-motion`.

| Страница | Файл | Что показывает |
|---|---|---|
| Главная | [`index.html`](index.html) | 12 экранов скролла, см. [STORYBOARD.md](STORYBOARD.md) |
| Внутренняя: «מעון ראשי — בית לחיים» | [`program-main-home.html`](program-main-home.html) | Шаблон страницы программы: крошки, «במבט אחד», галерея с доступным лайтбоксом, удобства, истории, «בשפה פשוטה», форма визита |
| Дизайн-система | [`design-system.html`](design-system.html) | Токены, живая проверка контраста, шрифтовая шкала, отступы, движение, все компоненты, форма вакансии |

## Как открыть

Нужен любой статический сервер: шрифты и модули по `file://` браузер не загрузит.

```bash
cd prototype
```

```bash
python3 -m http.server 8080
```

Затем открыть http://localhost:8080/ в браузере. Для проверки в режиме «меньше движения» включите *Reduce motion* в системе или нажмите «הפחתת תנועה באתר» в подвале.

## Структура

```
prototype/
├── index.html, program-main-home.html, design-system.html   ← СОБРАННЫЕ страницы (не править руками)
├── src/                                                     ← исходники страниц и partials (шапка, подвал, cookies, лайтбокс)
├── assets/
│   ├── css/tokens.css, main.css   ← исходники стилей;  site.css — склейка (генерируется)
│   ├── js/site.js                 ← UI: меню, cookies, видео-фасад, лента, лайтбокс, формы, переключатель движения
│   ├── js/motion.js               ← скролл-анимации GSAP (грузится после load; не грузится при reduced motion)
│   ├── vendor/gsap/               ← GSAP 3.15.1 + ScrollTrigger, локально (лицензия: README-gsap.md, gsap.com/standard-license)
│   ├── fonts/                     ← Frank Ruhl Libre + Assistant (OFL), подмножества core/latin + OFL.txt
│   └── img/                       ← 19 временных фото: AVIF + WebP, 480–1440px, без EXIF/GPS; manifest.json с alt
├── storyboard/                    ← 39 кадров раскадровки (десктоп и iPhone)
├── STORYBOARD.md                  ← раскадровка + спецификация каждой анимации
└── DESIGN-SYSTEM.md               ← токены, контраст, шкалы, компоненты, перенос в Elementor
```

Сборка (Python 3, без зависимостей):

```bash
python3 -I scripts/build_prototype_html.py
```

Скрипт собирает `src/*.html` → `*.html`, склеивает CSS и подставляет адаптивные `<picture>` из `assets/img/manifest.json`.

Фото пересобираются так (нужен Pillow; исходники — оригиналы с текущего сайта):

```bash
python3 -I scripts/build_prototype_images.py --src <папка_оригиналов> --out prototype/assets/img
```

## Что в прототипе временное

- **Логотип и все фото** взяты с текущего сайта. Это кадры **без узнаваемых лиц**: интерьеры, сад, мозаика, люди со спины. Перед запуском их заменит съёмка с оформленными согласиями ([бриф](../research/03-creative-directions.md#бриф-на-фотосъёмку-нужна-до-запуска)).
- Ссылки на ещё не сделанные страницы ведут на якоря главной.
- **Формы ничего не отправляют.** Это демонстрация валидации, сообщений и доступности. В WordPress отправка пойдёт через `wp_mail()` (шаг 3).
- Тексты на иврите — **предложение копирайта**. В них только подтверждённые факты. Неподтверждённое («с 1985», «семейный», точный адрес, число мест) в прототип не попало.
- Уведомления о приватности у форм — **черновик для юриста**.

## Проверки

Проведены 15.11.2026 в этой среде (Chromium 1243 через Playwright; Lighthouse 12.8.2; axe-core 4.14.0).

**Доступность (axe-core).** Теги wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa и best-practice. Прогон на десктопе и iPhone 13 после полного прокрута страницы.

| Страница | Нарушений |
|---|---|
| index.html | **0** (46 проверок пройдено) |
| program-main-home.html | **0** (52–53) |
| design-system.html | **0** (57) |

Axe не может сам посчитать контраст на градиентах (маркер `.nh-hl`), такие проверки он помечает как incomplete. Пары посчитаны вручную: ink на `citrus-100` — 12.8:1. Если запустить axe прямо во время анимации появления, он может зацепить полупрозрачный элемент. В покое нарушений нет.

**Функциональные проверки (скрипт Playwright):**
- Порядок Tab: «דילוג לתוכן» → баннер cookies → логотип → навигация. У всех элементов видимое кольцо фокуса 3px.
- Cookies: баннер есть при первом визите, выбор сохраняется, повторно открывается из подвала.
- Видео: до согласия **0 запросов к YouTube**.
- Лайтбокс открывается с клавиатуры. ← даёт следующую (RTL), → предыдущую, Esc закрывает, фокус возвращается на миниатюру. Живой регион читает «תמונה 2 מתוך 6. <alt>».
- Форма:
  - при пустой отправке появляется сводка с 3 ошибками, фокус переходит на неё, у полей стоят `aria-invalid` и `aria-describedby`;
  - корректные данные дают сообщение об успехе;
  - неверный телефон и e-mail дают понятные ошибки на иврите.
- Reduced motion (iPhone): весь контент виден, GSAP не грузится, горизонтального скролла нет.
- Мобильное меню: Esc закрывает, фокус возвращается на кнопку.
- Нет кликабельных целей меньше 24×24px (2.5.8).

**Lighthouse (мобильный профиль: эмуляция медленного 4G и 4× CPU; локальный сервер со сжатием brotli):**

| Страница | Performance | Accessibility | Best Practices | SEO | LCP | CLS | TBT |
|---|---|---|---|---|---|---|---|
| index.html | **95–96** | 100 | 100 | 63* | 2.5 с | 0 | 130–170 мс |
| program-main-home.html | **98–99** | 100 | 100 | 63* | 2.2–2.3 с | 0 | 0–70 мс |
| design-system.html | 99–100 | 100 | 100 | 63* | 1.7 с | 0 | 0–10 мс |

\* SEO 63 — только из-за `noindex`: прототип намеренно закрыт от индексации.

Что дало такие цифры:
- вход в hero на CSS;
- GSAP грузится после `load`;
- шрифты разрезаны на подмножества (критический путь 46 КБ);
- hero-фото предзагружается только на десктопе;
- один CSS-файл;
- AVIF/WebP с `srcset`;
- явные размеры у всех изображений (CLS 0).

**Не проверено здесь** (будет на шаге 5):
- реальные Safari (macOS/iOS), Firefox, Android Chrome — в среде есть только Chromium; «iPhone 13» выше — эмуляция в Chromium, а не Safari;
- реальные скринридеры (NVDA, VoiceOver);
- Lighthouse на настоящем WordPress-сайте.
