# Страницы и шаблоны Elementor (шаг 4)

## Что здесь

| Файл | Что это |
|---|---|
| `pages/home.json` | Главная (`דף הבית`, слаг `דף-הבית`), статическая главная страница сайта: 11 разворотов прототипа `index.html` |
| `pages/main-home.json` | «מעון ראשי — בית לחיים» (как `<title>` прототипа), слаг старого сайта `מעון-ראשי-בית-לחיים` ([redirects.csv](../content/redirects.csv)): 8 разворотов `program-main-home.html` |
| `pages/header.json`, `pages/footer.json` | Шаблоны Theme Builder (Elementor Pro), условие «весь сайт»: шапка — виджет `nh-masthead`; подвал (v3.2) — штатные виджеты Elementor (Image с эмблемой и Heading с названием — в одной строке, вложенный контейнер-ряд 44 px; Text Editor во вложенных контейнерах: сетка 5fr 3fr 4fr, на планшете две колонки, на телефоне одна; отступы, размеры и поля — как в прототипе: название ступенью «лид» `clamp()`, фраза 34ch, колофон 104ch, поле по бокам `clamp(1rem, .6rem + 3vw, 4rem)` на всех ширинах) и виджет `nh-display` («מצב רגוע»), без плагина подвал с навигацией, контактами и הצהרת נגישות остаётся ([research/07](../research/07-calm-v3.2.md) §12.6) |
| `media-map.json` | Имя фото → id вложения на тестовом сайте (пишет `test_site.py pages`, только номера) |

Файлы `pages/*.json` **генерируются, руками их не правят**: `python3 -I scripts/build_pages.py` берёт состав страниц из [`plugin/tests/fixtures/pages.php`](../plugin/tests/fixtures/pages.php) и настройки вариантов фикстур виджетов (через `plugin/tests/elementor_data.php` на стенде), затем проверяет рендер: каждый наш виджет и обе собранные страницы совпадают с фикстурами стенда байт в байт. Подвал из штатных виджетов собирает сам `build_pages.py` (тексты, цвета и шрифты — в настройках виджетов, Theme Style в Kit пустой); стенд штатные виджеты не рендерит, поэтому в подвале сверяется только `nh-display`, а остальное проверяют `lint()` (форма данных, типы виджетов, токены) и `test_site.py pages` на сайте (все виджеты на месте).

Поля файла: `key`, `title`, `slug`, `front_page`, `post_type`, `document_type` (`_elementor_template_type`), `template` (`_wp_page_template`), `conditions`, `page_settings` (`_elementor_page_settings`), `built_from` и `elementor_data` — значение `_elementor_data` в том виде, как его хранит Elementor 4.4.0: один контейнер (Full Width, колонка, gap 0, padding 0), в нём виджеты; у строк повторителей есть `_id`. В `built_from` кроме состава — из чего собрано: `plugin` (версия плагина и sha256 его PHP-файлов) и `inputs_sha256` (те же файлы плюс стенд, фикстуры, манифест фото и сам `build_pages.py`). Поэтому **после любой правки плагина или фикстур JSON надо пересобрать**: `test_site.py pages` откажется работать с файлами, собранными из другого дерева, а его шаг PHP — с сайтом, где PHP плагина не тот, под который собраны файлы (Elementor молча игнорирует незнакомые ключи, а повторитель, сохранённый целиком, хранит строки старого плагина).

Токены подставляются при выкладке: `@media:<имя>` — фото из `prototype/assets/img/manifest.json` или эмблема логотипа `@media:logo-emblem` (запись манифеста с `file`: PNG 105×74 грузится как есть, alt пустой) — в контроле `logo` шапки и в виджете Image подвала; `@page:<key>` — адрес нашей страницы; `@page-id:<key>` — её id (шапка отмечает «הבתים שלנו» на странице дома, `aria-current="true"`); `@home:<путь>` — `home_url()`. В HTML текстовых редакторов подвала шаг PHP один раз, при выкладке, читает настройки плагина: ссылки `#privacy`, `#accessibility`, `#sitemap`, `#entrances` становятся страницами из Settings → נווה האירוס (не заданная остаётся якорем), `@nh:email` — публичным e-mail (пока его нет, пункт списка с ним убирается). Ссылки меню в подвале — относительные `/#homes` и т. п. (разделы главной).

## Как выложить на тестовый сайт

```bash
python3 -I scripts/build_pages.py              # пересобрать JSON и проверить рендер (без сервера)
python3 -I scripts/test_site.py pages          # план: что будет сделано (только чтение)
python3 -I scripts/test_site.py pages --go     # выполнить
```

`--go`: 0) проверяет, что JSON собраны из этого дерева, и (если есть локальный PHP) прогоняет проверку рендера; 1) загружает фото (самый большой `.webp`, подразмеры делает WordPress; эмблему — её PNG как есть) с заголовком `nh:<имя>` и alt из манифеста (у эмблемы пустой) — уже загруженные находятся по заголовку и не грузятся снова; id вложения попадает в журнал и в `media-map.json` сразу, как WordPress его назвал; 2) одним шагом PHP от имени пользователя скрипта: до первой записи проверяет, что PHP плагина на сайте совпадает с тем, под который собраны файлы, и что в Elementor включена функция Container (без неё контейнеры не выводятся и страницы пусты); затем создаёт (черновиками) или обновляет 4 записи, найденные по мета-полю `_nh_page_key` (чужие записи не трогаются), пишет данные и мета Elementor, публикует их, пересобирает кэш условий Theme Builder и только после этого делает главную статической главной — если шаг упадёт раньше, главная сайта останется прежней; 3) очищает ezCache, проверяет обе страницы (200, нет ошибок PHP, все виджеты, шапка в обёртке `div`, подвал в `footer`, нет неразрешённых токенов) и печатает адреса. Старые значения и каждое изменение — в журнале `~/.config/nevehairus/test-site-changes.jsonl`: «Чтение» до запуска, а в ответе шага PHP — прежние условия Theme Builder и прежние данные наших записей (включая `_elementor_data`, если он отличался: правки, сделанные в редакторе, не теряются). Повторный запуск безопасен.

CSS Elementor этот шаг сам не чистит (только кэши CSS и ассетов своих четырёх записей): Elementor сам опустошает свой кэш CSS при каждом включении или выключении любого плагина, то есть и когда скрипт включает и выключает Code Snippets, и сам собирает его заново при следующем просмотре.

## Важно

- **Правки этих страниц в редакторе Elementor на сайте перезапишет следующий `pages --go`** (прежний `_elementor_data` останется только в журнале). Менять — в фикстурах или плагине и пересобирать.
- Обёртка шаблона шапки в Pro — `div` (настройка документа «HTML Tag»): ориентир `<header>` даёт виджет `nh-masthead`, как в прототипе (SPEC D3), без двойного ориентира. У шаблона подвала (v3.2) обёртка `footer`: ориентир даёт сам шаблон, внутри штатные виджеты.
- Настройки плагина (Settings → נווה האירוס: e-mail, страницы доступности и карты сайта, PDF входов) этот шаг не заполняет, а читает при выкладке: пока их нет, в подвале нет пункта e-mail, а ссылки `#accessibility` и т. п. остаются якорями. **После того как их заполнят, `pages --go` надо повторить** — подвал статичный, сам он настройки не перечитывает.
- Год в строке «© {год}» — динамический тег Pro «Current Date Time» (формат `Y`) в Text Editor; его настройки (`date_format: custom`, `custom_format: Y`, `before`/`after`) взяты по исходникам ядра Elementor 4.4.0 (формат тега) и не сверены с исходниками тега Pro: проверить на тестовом сайте.
- Ссылки в данных абсолютные, как их сохраняет сам Elementor: `@home:` и `@page:` становятся `https://nevehairus.ussl.co.il/…`, адреса фото тоже. При переносе на другой домен — Elementor → Tools → Replace URL (в JSON слэши экранированы, обычная замена строки их не найдёт).
- `post_content` у страниц пустой: Elementor пишет туда текстовую копию только при сохранении в редакторе, так что поиск WordPress и SEO-плагины не видят текста страниц, пока их не сохранят в редакторе. Для показа страниц это не нужно.
